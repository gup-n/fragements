# 碎片

[![android](https://github.com/gup-n/fragements/actions/workflows/android.yml/badge.svg)](https://github.com/gup-n/fragements/actions/workflows/android.yml)

> 随手扔一句，AI 分批帮你收拢，想不起来的时候还能问它。

个人用、单机、Android 侧载的碎片记录工具。记录时不分类、不打断；整理时 AI 一批一批地过，
全部跑完再统一确认；想找东西时直接问，答不上可以开联网。

| | |
|---|---|
| 应用名 | 碎片 |
| 包名 | `com.local.fragments`（固定，改包名等于换 App，旧数据不跟随） |
| 当前版本 | v0.20.1（versionCode 52） |
| 目标设备 | vivo Y78（V2278A），`targetSdk 36` / `minSdk 24` |
| 数据 | 本地 SQLite，无账号、无服务器、无云同步 |

## 第一次装上

1. **下载安装包**：[Releases](https://github.com/gup-n/fragements/releases/latest) 里的 `fragments-v0.12.0.apk`。
   首次安装系统会拦「未知来源」，允许一次即可（这也是 App 内更新的前提）。
2. **填 API Key**：设置 → 配置 → 模型服务。`Base URL` 和 `模型` 已经填好默认值
   （`https://api.deepseek.com/v1` / `deepseek-flash`），只需要贴一个 Key；
   Key 去 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys) 建，存在手机的 Android Keystore 里。
3. **记第一条**：回时间轴，底部输入框写一句就走。**不用分类、不用挑标签** —— 分类是整理时的事。
4. **攒够十几条再整理**：一次几十条效果最好，三五条跑一趟只是多花钱。
   跑完会出确认页，勾选后才写库。
5. **马上做一次备份**：设置 → 数据 → 导出 Markdown，存到电脑或网盘。
   数据只在手机本地，**卸载即全部丢失**，这个出口是唯一的。

之后想更新：启动 3 秒会自己查新版本，也可以在设置 → 关于 → 检查更新里手动点。
不装新包也能用，旧版本不会失效 —— 只有换模型、加原生能力这类改动才必须升级。

## 两条设计红线

1. **记录摩擦必须极低**。打开即输入，输完即走。任何「先选分类再写」的设计都违背定位。
2. **AI 只做收拢，不做限制**。AI 从不阻止你记录，只在你想整理时提供建议。

## 工程约定

| 约定 | 原因 |
|---|---|
| 只做单机，不引入账号 / 后端 / 云同步 | 数据在手机上，没有服务器就没有泄露面 |
| AI 结果必须逐条确认才写库 | 决不自动改用户数据 |
| 永不删除用户原文 | 去重只写 `merged_into` 标记，原文保留并置灰 |
| 破坏性操作默认不勾选 | 勾了才会删待办 / 合并待办 / 合并碎片（标完成例外） |
| 数据必须能迁出，**也能迁回** | Markdown 是底线能力。只导出不导入等于没有备份，两边都要能跑 |
| 存储层用 `.native.ts` / `.web.ts` 分流 | 业务代码统一 `import from '../db/repo'`，由 Metro 按平台解析 |
| 改功能先改 SPEC 再改代码 | SPEC 是跨会话的唯一依据 |

## 现在能做什么

**外观**：浅色 / 深色 / 跟随系统，设置页第一项，改完立刻生效。默认跟随系统 ——
系统切深色界面跟着切，不用重启。启动屏也会跟着系统走，深色下点开不会先闪一下白。

**记录**：时间轴流按日分组，默认只展开今天、往前的日期收成「日期 + 条数 + 首条摘要」，点一下展开。
更早的月份折成「10月小结 / 10月记录」两块；**展开后是两级折叠** ——
月头点一下收起，月里的每一天也各占一行（10月11日 · 3 条），点一下才铺开那天的内容。
不会几十条连成一片，也不用一天天盲点。

**配图（v0.20 起可以多张，v0.20.1 起能插在正文中间）**：输入框下方一排工具 —— 「展开」在左，
**「图片」和「发布」都在右**。
点图片可以「拍一张」或「从相册选（可多选）」，选好的图在输入框里横排，点叉号去掉某一张；
一条最多 9 张，不写字也能发。
发出去之后模型会**逐张**把图里的字读出来存好 —— 整理、问答、**搜索**都能用上
（搜「0x8007」能命中那张蓝屏截图）。时间轴上显示一排缩略图 + 一行状态
（「正在读图里的字…」/「有 N 张没读出文字 · 点这里重试」/ 图文字预览）。

**想在文字中间插一张图**：展开成长文（或进详情页点「编辑」），把光标放到要插图的位置，
点底部的图片按钮 —— 图就长在那段话中间，不再统一堆在正文最上面。详情页里点任意一张图
可以全屏看（黑底、左右翻、点一下退出），编辑态能逐张删图（要点两次）。
没在正文里定位过的图，仍然铺在正文上方 —— 老碎片完全不受影响。

> 为什么是「读一次存成文字」而不是每次把图发给模型：一张图最多 1024 token，
> 40 条碎片里十几张图会让每轮整理重复付费；而且图里的字不进索引，搜不到。
> 原图一直留在手机上，点开随时能看。导出的 Markdown 只带文字，不带图片文件。
顶部搜索框直接过滤碎片原文 / 事项。**命中会描底色**，每条右侧标出「N 处」，
统计行给「找到 5 条 · 12 处」；点进详情后顶部有「第 1 / 3 处」和上下箭头，逐处跳过去
（按实测段落位置滚，不是按字数估）。长文超过 100 字或含换行自动折叠。
碎片正文现在按 Markdown 渲染：`##` 标题、`- ` 列表、表格、代码块、加粗和行内代码都会正常排版（v0.8.9）。
点一条进全屏详情页，左右滑动看上一条 / 下一条，右上角「编辑」**原地整屏改**，正文下方接着所属月份的月总结。
点事项名可以只看同类（和搜索框叠乘，有筛选时所有日期自动展开），再点一次取消。
**长按一条 = 复制正文**（底部会提示「已复制」）；**左滑露出「删除」**，点了还要再确认一次；
**右滑直接进「问」**，并自动带上这条碎片作为上下文 —— 不用先复制再去问页粘贴。

**整理（v0.17 重做，v0.18 修「说出所有却只整理 40 条」）**：整理不再是单独一页，也不再是「一大坨正文」。
它在「问」里：空态点「整理碎片」，或者直接说一句「把这些碎片整理一下」。
说 **「整理所有碎片」** 就是真的全库：按 40 条一批往下跑，每批跑完记下游标，
中途退出下次接着来；一轮跑不完时卡片上会写「还有 N 条没整理，继续」。

- **只收能复用的知识**：做法与顺序、结论与判断、参数与报错、方案对比。
  生活琐事、情绪、计划、没验证过的猜测一概不收 —— **三个月后重读还能照着做，才算知识**。
  一批碎片里全是琐事时，它会直说「这次没有可沉淀的知识」，不硬凑一篇。
- **按主题拆成 1~4 篇**，每篇 200~800 字。材料里没那么多知识就写短，不注水。
  「换盘步骤」和「报错含义」不再挤在同一篇里，找具体做法不用从头读。
- **过程看得见**：读到几条碎片、拆出几篇、正在写《哪一篇》，一行一行往下走；
  思考过程生成中默认摊开，之后可以收起再点开。
- **产出是几张小卡**：标题、字数、一句话摘要；点开**是一整页**（不在对话里挤），
  页内「阅读 / 编辑」两态，表格是真渲染出来的，不是一串竖线。
  不满意可以继续说一句「第二篇并进第一篇」，它只改你点到的地方。
- **整理会留在历史里**：每次整理写一条记录（你那句话 + 产出了几篇、几件事），
  退出再回来还找得到，和问答一样能跳文档、能重新整理。
- **每篇可以单独「加入文档库」**，也能全部加入；写入前有两个权限位
  （写文档 / 新增待办），默认开但看得见、关得掉。**原碎片一个字不动。**
- **报错不省略**：状态码、`finish_reason`、服务端或模型的原话都在「查看详情」里 ——
  只给一句「再试一次」等于把唯一能定位问题的东西扔了。

**问（v0.7.1 新增，v0.8.8 重构）**：像聊天一样问自己的记录。回答只依据检索到的碎片 / 小结 / 待办，
模型内部仍然按 `[F12]` 引用，但界面上看到的是**一枚可点的小标**：点开从底部展开这条引用当时的原文，
不会再看到「[F55]」这种只有模型知道是什么的字符串。回答里的表格、代码块、分隔线都会正常排版（v0.8.7）——
说一句「列个表给我」，看到的是格子而不是一串竖线。两个开关跟 DeepSeek 手机 App 一样：
**深度思考**（提高推理强度）、**联网搜索**（本地查不到就上网，与本地检索并行，失败不影响本地回答）。

联网分两条路（v0.19.1）：**你发链接，它就去读那一页**（`/v1/tools/fetch`，整页 Markdown）；
没发链接才按关键词搜（`/v1/tools/search`）。以前不管发什么都拿去搜，链接作为搜索词
搜不出东西，界面就说「没搜到有用的网页」—— 看起来像没联网，其实是根本没去读。
提示现在也分开说：`读了 1 个链接` / `联网补了 3 条网页资料` / `联网没成：<原因>`。
深度思考的思维链**答完不会消失**：会收成一块「深度思考 · N 字」，点一下展开，刚答完那一轮默认展开（v0.8.9）。

**历史会话**：每答完一轮自动存进历史，退出不再弹「要不要留纪要」。
**从左往右滑把历史抽屉拉出来**（手指拖多少它跟多少，松手过半才展开），
往左滑推回去；左上角也有按钮。按 今天 / 昨天 / 更早 分组；
每条右侧「…」可以**归档 / 整理成文档 / 重新整理 / 删除**。
整理过的会话行会带「已写入文档」徽标（多篇时是「已写入 2 篇」，点开先列出来再选）；
「重新整理」用**当初那批碎片**重跑，不是拿「最近 40 条」凑一遍。
删除会话**不会删文档** —— 文档已经是独立的一篇东西了。
右上角「+」开新会话（已经在新会话里时，顶部会闪一句「已在新对话中」），「×」退出；
安卓返回键同样回到主界面。

**文档（v0.12.0 重做，v0.16 加知识文档）**：页头「问」左边的文件图标。它同时装两类东西：
你导入的原件，和**整理出来的知识文档**（没有原件，只有正文）。后者在列表里直接铺三行摘要，
不用点开才知道写了什么；顶部搜索框查标题、摘要和正文三处，找「哪篇里写过群晖」不用一个个点开。

一个工作区，而不是「上传换个解析结果」：

**导入只保存。** 选完文件就复制进 App 私有目录，显示「已保存」——不解析、不建索引、
不发任何网络请求。飞行模式、没填 AI Key、没填 MinerU Token，都能把文件存进来。
以前是「格式不在解析白名单里就传不进来」，这条已经去掉了：**存不存得下**和
「能不能解析」是两件事。

**能读，也能搜。** 四种格式有应用内只读视图：

| 格式 | 打开后能做什么 | 谁来解 |
|---|---|---|
| PDF | 原版式翻页缩放、全文查找（跨页）、提取文字层 | 本地 PDF.js，零上传 |
| Excel（xlsx / xls） | 工作表切换、单元格只看、按格查找 | 本地 SheetJS，零上传 |
| Markdown | 排版阅读 / 原文两种模式、查找 | 本地 |
| TXT | 纯文本、查找 | 本地 |
| Word / PPT | 云解析出来的正文（版式会失真），查找 | 云解析后本地读 |

阅读器里的查找框会显示「第 i / N 处」并逐处跳转，和碎片搜索是同一套口径。
**快过 99 处显示「99+」**，不假装总共只有 99。PDF 打开时先画第一页，
文字索引在后台建 —— 这期间查找框写「正在索引文字…」而不是「没有找到」。
扫描版 PDF 能翻页但没有文字层，这时会直说「这份没有文字层，不能查找也不能提问」，
不会报「全文无命中」。

**能问，但只问选中的。** 列表里多选（最多 8 份），底部「问这 N 份文档」；
阅读器里也有「问这份」。问答**只查这几份**，不混笔记、不混其他文档、默认不联网。
选的里面有过期或没准备好的，会先列出哪几份待准备，让你决定准备还是移除 ——
**不会静默丢掉几份然后照常回答**。

回答里的引用能点开看原文片段，并标出真实位置（《方案.pdf》第 3 页 / 某个工作表的
某个单元格 / 第几行）。没有定位信息的旧文档只写「正文第 N 段」，**不编页码**。

**大文件与旧格式仍然走云解析**，那部分和 v0.12.0 一样：

| 通道 | 要 Token | 上限 | 认的格式 |
|---|---|---|---|
| 轻量（默认） | 不要 | 10 MB / 20 页 | PDF、图片、docx、pptx、**xlsx** |
| 精准 | 要 | 200 MB / 200 页，每天 1000 页 | 上面全部 + doc / ppt / xls |

Token 在 设置 → 配置 → 文档解析 里填。云解析**每次都要确认**（含重试和换通道），
确认卡上写明「文件会上传到 mineru.net」。CSV 两个接口都不认，先另存为 txt 或 xlsx。

本地上限：PDF 48 MB / 300 页、Excel 12 MB / 10 万单元格、纯文本 4 MB、正文 200 万字。
超了就明确告诉你超了哪一条，**原件照样保留、照样能用外部应用打开**，不会悄悄截断。

**月总结**：只有月这一种粒度（日、周两种在 v0.15 删掉了——一天记三五条碎片，
压出来的那段话基本是原文的缩写，读回来的价值低于它占据的时间轴位置）。
AI 把该月**全部**碎片读一遍写成 Markdown，**先预览再决定存不存**。
三节固定为「重点 / 进展 / 待处理」，没有内容的整节省略；500 字是**上限**不是目标，
写得比上限短是正常的。

能做的操作：

- **滑动读**：点开任意一篇进全屏阅读器，左右滑动在列表里那批之间切换
- **对照**：重新生成一个有旧稿的月份，预览页左旧右新并排，各标字数
- **批量**：勾选「还没写的 N 个月」排队跑，每篇仍然单独预览、单独确认

存下后落在时间轴该月**最后一天**，排在那天所有碎片前面。

**整理状态**：整理产出的文档**真正写进文档库之后**，那批来源碎片会打上「已整理」胶囊 ——
一眼看得出哪些还没整理过，不用凭记忆。设置页的「待整理」也按这个口径数（v0.18.1）。
标签模块（胶囊、按标签筛、回顾页的标签 tab）已经整个拆掉：AI 从 v0.7 起就不打标签了，
留着只是让旧数据当摆设。

待办（v0.15 重做）不再只能由 AI 整理产生：

- **两层子项**：一条待办下面可以挂几步。勾父项＝连同子项一起完成；
  子项一个个勾完，父项自己变成完成；取消任一子项，父项退回未完成。
- **自己写**：顶部「新建」，或父项右侧的「＋」加一条子项。
- **改**：点文字进编辑层，改内容与到期日（今天 / 明天 / 清除）。
- **合并**：进入合并模式勾选几条，写下合并后的那一句；被合并的收在「已合并 N 条」里，随时能恢复。
- 点击完成、显示截止日（过期标红）、已完成置灰划线；已完成只保留最近 5 条，更早的会被清理。

**导出 / 导入**：导出是一个 .md 文件（时间轴按天分节 + 待办清单 + 标签索引），
走系统分享可直接存到电脑或网盘。导入反过来：**先预览再写库**——共读到多少条、跨哪几天、
会导入多少、跳过多少重复，看清了才点确认。同一个文件导两遍不会翻倍（按「天 + 分钟 + 正文」判重）。

**索引可见**：设置 → 数据 里显示搜索索引的健康度 —— 「索引完整 · 132 条全部可搜」
加一行抽样自检。自检取每条的**两段**正文往回搜，任一段能定位到自己就算通过
（只取一段会撞上「明天上午」这类高频词，命中太多、自己排在后面，被误判成搜不回）。
结论给三句话之一：「N 条全部搜回」/「N 条全部能搜到（其中 M 条内容重复，不影响搜索）」/「N 条里 M 条能搜回」，
最后一种才会列出具体的 `#id` 和用过的检索词，并建议点「重建搜索索引」。

**更新**：启动 3 秒后自动查一次 GitHub Release，有新版本弹窗提示；设置里可以关掉自动检查，
也可以随时手动点「检查更新」。下载带进度条（**下载源 · 已下载 / 总大小 · 实时速度**），下完交给系统安装器。
支持「不再提示这个版本」——勾了之后要等下一个版本才会再问。

**下载（v0.12.0 改了顺序）**：GitHub 的 APK 实际从 `objects.githubusercontent.com` 这类 CDN 下发，
大陆直连可能极慢。所以下载按「**自定义地址 → GitHub 官方 → 内置加速镜像**」尝试，哪个先通走哪个。
**官方排在镜像前面**是实测的结果：镜像时快时慢，而「时快时慢」比「一直慢」更难受。
每个源都有停滞检测——15 秒没有新字节、或者跑满 60 秒平均低于 25 KB/s 且进度没过三成，
就自动掐掉换下一个，不会让你对着一个不动的进度条等。
设置 → 关于 → 「下载地址」可以填自建或镜像的基础地址（以 `/` 结尾，下载时拼上 APK 文件名）。

下载时通知栏有一条常驻通知「正在下载 v0.9.0 · 8.2 / 22.3 MB · 37%」。**这里有个必须知道的限制**：
Android 上 Expo 没有前台服务，切到后台后传输会继续（进程不被杀就行），但 JS 线程被挂起，
**通知里的百分比会停在切走那一刻**，回到应用才接上。所以它承诺的是「状态可见」，不是「数字实时」。

> 更新源是 **GitHub Release**，不是 Actions 的 artifact —— 后者下载要登录。
> 发版流程因此变成：`git tag v0.9.0 && git push origin v0.9.0`，CI 自动建 Release 并挂 APK。

**尚未实现**：通知栏常驻的「快速记录」入口（和上面那条下载通知是两件事）。见 [ROADMAP.md](./ROADMAP.md) P0-2。

## 开发

```bash
npm run typecheck           # tsc --noEmit，改完必跑（项目没有 lint、没有单测）
npm run test:md             # 导入导出往返断言（碎片 → md → 碎片，两次必须一致）
npm run check:docs          # 文档一致性：版本号 / 行数表 / 死链 / 提示词抄录
npm run build:web           # Web 平台打一遍包，量完体积就删 —— 只当编译校验，不产出预览
npx expo start              # dev server，手机 Expo Go 扫码
```

> **不做界面预览**（用户 2026-10-25 明确要求）。`build:web` 的产物落在 `.tmp-bundle/`
> 并在同一次运行里删掉，根目录不会留下能起静态服务的东西；UI 只靠装 APK 真机反馈验证。

新增依赖用 `npm install <pkg>@<与 SDK 匹配的版本> --registry=https://registry.npmmirror.com`。
`npx expo install` 在这台机器上曾卡 9 分钟无输出（其实已经装好了），所以不用它；
版本号自己核对 `npm view <pkg> versions`，装完确认 `package.json` 里记上了 —— npm 超时被杀时可能只解包、不写清单。

## 构建 APK

```bash
npx expo prebuild --platform android --no-install --no-clean   # --no-clean 不能省
cd android && ./gradlew assembleRelease                         # 增量约 2~3 分钟
```

产物：`android/app/build/outputs/apk/release/app-release.apk`（约 22 MB）

体积与速度已做过针对性优化。**配置的源头是 [`plugins/withBuildOptimizations.js`](./plugins/withBuildOptimizations.js)**，它在每次 prebuild 时把属性写进 `android/gradle.properties`：

| 配置 | 作用 |
|---|---|
| `reactNativeArchitectures=arm64-v8a` | 只打 64 位 ARM。原来打 4 种 ABI，APK 75 MB、C++ 编译量翻 4 倍 |
| `expo.gif.enabled=false` / `expo.webp.enabled=false` | 项目未使用 RN 的 `<Image>`，关掉可移除 Fresco 相关原生库 |
| `android.enableShrinkResourcesInReleaseBuilds=true` | 移除未引用资源 |
| `org.gradle.jvmargs=-Xmx4096m` + `caching` + `workers.max=8` | 本机 15.7 G 内存 / 20 线程，加大堆并限制并行度避免 GC 抖动 |
| 图标按需导入 | `import Ionicons from '@expo/vector-icons/Ionicons'`，避免把 19 套字体全打进包（3.3 MB → 0.38 MB） |

**这一步有三个必看的坑**（JDK 路径、Windows 260 字符路径限制、prebuild 会重置 android 配置），
详细说明见 [SPEC.md 第 12 节](./SPEC.md#12-本地打包-apk)。首次全量约 45 分钟。

体积对照：76 MB（v0.1.1，4 ABI）→ 22 MB（v0.2.0），减少 **71%**。

### 自动构建（GitHub Actions）

推到 `master` 或打 `v*` tag 会触发 [`.github/workflows/android.yml`](./.github/workflows/android.yml)：
装依赖 → `tsc --noEmit` → `npm run test:md` → `npm run check:docs` → prebuild → `assembleRelease`，
产物是名为 `fragments-apk` 的 artifact，挂在这次运行页面底部（保留 30 天）。

实测一次约 **8 分钟**（Gradle 缓存命中后更快）。`release` 沿用 debug 签名，
所以不需要任何 secret —— 仓库是公开的，签名密钥不该进 CI。

改 workflow 时有两个坑：

- **别加 `android-actions/setup-android`。** ubuntu-latest 镜像自带 SDK
  （`/usr/local/lib/android/sdk`），它再去装一遍会和预装目录抢，v0.8.3 第一次 CI
  就挂在这一步。
- **Gradle 缓存要放在 prebuild 之后。** `gradle-wrapper.properties` 是 prebuild
  生成的，提前取 `hashFiles` 永远是空字符串，等于每次换一把新锁。

### 文档一致性检查

```bash
npm run check:docs
```

七项机器可查的东西：三处版本号是否一致、HANDOFF 的文件行数表、相对链接是否有死链、
引用的 `src/...` 路径是否存在、`文件:行号` 是否还落在有内容的行上、
`TEXTS.md` 抄录的提示词是否与源码逐行相同、各文档写的「N 条清单」是否等于 ROADMAP 实际条数。

写这个脚本的原因很直接：这之前每一版都靠人眼扫文档，而**看不出来的时候不知道自己看不出来**。
v0.8.6 → v0.8.7 之间它一次就抓出 9 处行数漂移、2 处行号漂移、1 处版本没更。
CI 里排在 `test:md` 之后，秒级完成。

## Android 平台约束（改 UI 前先看）

`targetSdk 36` 让 RN 强制开启 edge-to-edge，`windowSoftInputMode="adjustResize"` 因此失效，输入法只是盖在窗口上。四条硬规则：

| 规则 | 原因 |
|---|---|
| 键盘遮挡用 `useKeyboardHeight()` 加 `paddingBottom` | `KeyboardAvoidingView` 在 RN 0.88 + edge-to-edge 下算出的位移恒为 0，等于没生效 |
| 全屏页 / 弹层用 `position:absolute` 覆盖层，不用 `Modal` | Modal 是独立 Dialog 窗口，带 `FLAG_LAYOUT_NO_LIMITS` 会画到状态栏下，且收不到键盘事件 |
| 覆盖层自己接 `BackHandler` | 没有 Modal 的 `onRequestClose` 兜底，返回键会直接退出 App |
| 启动窗、`AppTheme.windowBackground`、页面底色三者同色 | 任意两段不同色就会看见一次闪白 |

细节与踩坑过程见 [SPEC.md 8.1 节](./SPEC.md#81-android-适配红线v021-真机踩过后定下)。

## 数据安全

**数据只存在手机本地的 SQLite 里，卸载 App 即全部丢失。** 备份出口是
「设置 → 数据 → 导出 Markdown」，建议定期导出到电脑或其他设备；换手机或重装后，
用同一个入口下方的「从 Markdown 导入」往回装。

导出格式里不含 `status` / `project` / 合并关系，导回来按「有标签=已整理」推断；
多行正文在导出时就已经压成一行了。这两点是有损的，知道比不知道好。

API Key 存在 Android Keystore 加密区，不进源码、不进仓库、不上传任何服务器。

**默认不出手机，出手机必须你点确认**：PDF / Excel / txt / md 的阅读与提取全在本机
（PDF.js、SheetJS），不发任何请求。只有两种情况会往外发：

- **云解析**（Word / PPT / 图片，或你主动对大文件选「云解析」）：整个原文件上传到
  mineru.net，确认卡上写明接收方、文件、通道和上限，点「开始解析」才发。
- **文档问答**：只把你选中的那几份文档的**相关片段**发给配置好的 AI 服务，按下发送才发。

原文件始终留在手机私有目录，删除记录时一起删。已上传的字节撤不回来，确认卡上也这么写。
