# 碎片

[![android](https://github.com/gup-n/fragements/actions/workflows/android.yml/badge.svg)](https://github.com/gup-n/fragements/actions/workflows/android.yml)

> 随手记，在同一个地方提问和整理；确认后再把有用的内容留下。

个人单机 Android 记录工具。记录时不要求分类；「问」负责问答、整理碎片、整理待办和发起月总结。没有账号、应用后端或云同步；**这不表示 AI、联网搜索和云解析不会发送资料**，外发边界见下文。

**本分支状态：开发中，尚未发布。** 2026-11-14 获批的纸面 UI、墨水风格和可靠性改版正在整合验证。版本号仍沿用 v0.20.4；现有 Release 不等于本分支的新功能，不能据此宣称用户已可下载安装新版。

## 1. 产品与基本用法

### 随手记

- 时间轴按日/月折叠；搜索或事项筛选时展开结果。点击记录进详情，左右翻阅当前列表中的记录。
- 输入区文字占整行，工具在下方：展开在左，图片与发布在右。相机/相册选择行放在输入区内部。
- 一条最多9张图片，可以只发图片，也能在长文光标处插图。详情保留图片原比例，可全屏看图；删除记录或配图仍需明确确认。
- 长按复制；左滑露出删除并二次确认；右滑进入「问」并带上该条记录。编辑在详情页内完成。
- 标签入口已下线。旧 `tags` 数据只保留兼容用途，不恢复标签页、胶囊或按标签筛选。

### 问与整理

- 问答按需检索碎片、月总结和待办，不把整库原文直接塞给模型。来源以引用小标展示，历史引用使用当时的快照。
- 「深度思考」与「联网」分别控制。联网开启后，有链接走页面读取，没有链接走搜索；外部资料失败不冒充成功，也不应阻断本地资料的回答。
- 整理没有独立页面，仍在聊天中进行：用户消息在右、助手正文在左。草稿可逐篇查看/编辑，并可继续提出修改要求。
- 整理产出是**知识文档和待办，不是新的碎片**。只收材料中可复用的事实、做法与结论；没有可沉淀内容时如实说明，不凑文章。
- 写文档、加待办有独立权限，产出项也有选择状态。用户确认后才写入；整理不改写来源碎片原文。
- 历史会话存入会话表，不自动变成时间轴记录。删除会话不连带删除已生成文档。

### 回顾与设置

- 回顾只有待办和小结，没有标签 tab。待办支持两层父子项、编辑、到期日、合并与恢复。
- 月总结是现行生成粒度：按日事件表与重要事件/进展，先审阅再保存；已有稿可对照，缺口可排队生成并逐篇确认。旧类型只用于历史兼容，不恢复日/周生成入口。
- **已完成待办沿用“只保留最近5条”的既有清理规则**，不是永久归档。
- 设置仍是配置、外观、数据、关于四个模块及对应子页，不为同一个子页重复造入口。

## 2. 本次改版内容（开发中、未发布）

设计依据是 [SPEC 的批准节](<SPEC.md#2026-11-14-已批准可靠性修复与两轴外观>)、[方案 A](<docs/plans/2026-11-14-ui-refresh-ink-proposal.md>) 和[实施契约](<docs/plans/2026-11-14-implementation-contracts.md>)。下面说明当前开发方向与代码范围，**不是发布说明或真机验收结论**。

| 改动 | 本分支的实现边界 |
|---|---|
| 两轴外观 | 明暗为浅/深/跟随系统，风格为默认/墨水；各自保存，互不重置。墨水不是设备级墨水屏驱动，也不反相或灰度照片/PDF原稿 |
| 阅读与控件 | 克制纸面布局、动态边线、真实48dp点击槽；必要状态与当前命中增加文字、勾选、下划线或轮廓；墨水/系统减少动效时减少装饰运动 |
| 阅读空间 | 文档次要操作收进有文字的展开区，主要动作保留；能读不再绑定能问，云上传和删除确认不隐藏 |
| 记录可靠性 | 正文、图片定位与索引的提交边界一致；提交后的刷新失败不再作为清理已引用图片的理由 |
| 草稿生命周期 | 正文、待发图片与唯一待发键由页面外持有，切页/换风格不应丢失。记录草稿仍是当前 App 生命周期内的状态，不等于重启恢复 |
| 检索与文字迁出 | 可见搜索投影包含正文、已有图文字和事项，不含隐藏旧标签；导出独立读取全部碎片，不复用首页窗口 |
| 整理可靠性 | 稳定草稿/条目身份、保留逐项授权、原子提交凭据、真实会话来源提炼、原材料重试；全量范围采用id快照，草稿和进度一起持久化，恢复不自动重发请求 |

冷启动原生窗口早于 JS 偏好加载；目前没有原生偏好桥，因此不承诺所有启动场景零闪烁。新界面、中文输入法、TalkBack、手势和原生 WebView 仍待设备验证。

## 3. 文档：保存、阅读、准备、提问是四件事

**添加文档只保存原件副本与元数据**，不自动解析、建索引或上传。飞行模式和没有 Key/Token 不应成为保存原件的门槛；空间不足或复制失败会报错。

| 格式 | 本机阅读能力 |
|---|---|
| PDF | 本地 PDF.js 原版式显示与缩放；有文字层时可跨页字面查找。扫描件可看页面，但不能把没有文字层说成“零命中” |
| Excel / CSV | 本地只读工作表、单元格与查找；公式只读缓存值，不执行宏 |
| Markdown | 排版阅读与本地查找；作者的 `[F12]` 等字面文字不当作应用引用吞掉 |
| TXT | 原文阅读与本地查找，不按 Markdown 改写展示 |
| Word / PPT / 文档图片 | 可用外部应用打开原件；已有云解析正文时可读文本快照，不能冒充原版式 |

本机边界来自[格式与容量判据](<src/documents/formats.ts>)：PDF 48 MB / 300页，Excel 12 MB / 10万有效单元格，文本4 MB，规范正文200万字。显示裁列、命中超限或阅读超限必须明确提示；原件不因阅读超限而丢弃。

阅读器内查找是字面匹配，不拿 FTS 的相关候选数冒充全文命中数。超过99处显示“99+”；定位只使用真实页码、工作表/行列、文本行或正文块，不能从旧 Markdown 猜 PDF 页码。

文档提问最多选8份。只有正文、内容版本和索引版本就绪的文档才能问；未就绪项先列明，由用户决定准备或移除，不静默丢弃。文档会话锁定所选范围，不混入其它记录，默认关闭联网。

### 外发边界

| 动作 | 会离开手机的内容 |
|---|---|
| 记录、导入、阅读、本地查找/提取 | 本地操作，不因此发送用户资料 |
| 用户发起问答/整理、手动读图 | 向配置的 AI 服务发送所需资料；读图会发送选中图片的图像内容，不只是已有OCR文字。自动按需读图只发生在整理/提问准备阶段，不在保存图片时发生 |
| 开启联网后发送问题 | 向搜索/页面读取服务发送查询或链接；结果作为不可信资料使用 |
| 云解析 | 向 `mineru.net` 发送整份原文件；**首次、重试和换通道每次都先确认** |
| Markdown 导出/打开原件 | 用户选择系统分享目标或外部应用后，内容交给该目标；不是自动云同步 |

MinerU 轻量通道免Token，上限10 MB / 20页；精准通道需Token，上限200 MB / 200页，并消耗其每日页数额度。当前确认卡与通道判据负责说明实际可用性；不要把云端配额当作本地导入上限。取消不能撤回已经上传的字节。

API Key 存在系统安全存储中，用于请求所配置服务的认证；不得把密钥写入源码、Markdown 导出或公开日志。不能把“本地保存Key”写成“Key永远不会传给服务商”。

## 4. 文字迁出不是完整备份

设置 → 数据提供 Markdown 导出/导入，但它不是数据库和附件的完整恢复工具。

- 当前开发分支导出全部碎片的可读文字、分钟时间和旧标签；已有图片文字作为文本迁出，未读/无字配图带缺失说明，不临时调用AI读图。
- **不含原图文件、文档及原件、月总结、历史会话或完整数据库状态。** 事项、合并关系等不能原样重建；多行文字仍按兼容格式压成一行。
- 导出的待办清单只供阅读，当前导入不恢复待办。图片文字导入后也是普通正文，不恢复附件或OCR关联。
- 导入先审阅数量、时间跨度和日期警告，再确认写入。本分支在写入时重新判重并串行化导入；部分失败保留已经成功的条目，重试跳过已写入内容，不宣称整份文件原子回滚。
- 卸载、清空数据或丢失手机会失去本地库和私有文件。**不要仅凭一份Markdown就认为可以安全卸载。** 完整备份/恢复和原生迁移故障保障仍是单列风险。

Git恢复分支只恢复代码，不恢复手机数据；设置切回默认风格也不等于恢复旧版布局或降级APK。

## 5. 安装、开发与发布

已发布安装包以[GitHub Releases](https://github.com/gup-n/fragements/releases) 中的 raw APK asset 为准，不是需要登录下载的 Actions artifact压缩包。安装未知来源应用需按Android提示授权。**本分支改版还没有新Release，不能通过下载旧包验收新UI。**

技术栈为 React Native 0.88、Expo SDK 58、React 19.3、TypeScript 6、SQLite/FTS5与中文bigram；PDF.js、SheetJS、fflate承担本地阅读相关工作。路由由[App](<App.tsx>)的state管理，没有Expo Router、后端或新增导航库。

常用验证入口如下；本轮已在开发分支上由 Lead 串行实跑，结果见 [HANDOFF 的验证表](<HANDOFF.md#验证入口与范围>)。多人并行开发时仍由 Lead 统一执行。

| 入口 | 范围 |
|---|---|
| `npm run typecheck` | TypeScript类型检查 |
| `npm run test:md` | Markdown迁出/导入往返 |
| `npm run test:docs` | 文档问答、任务服务、阅读器纯逻辑 |
| `npm run test:todos` | 待办层级与月总结口径 |
| `npm run test:ask` | 指令路由与草稿规则 |
| `npm run test:reliability` | 真实控制流、故障注入、授权、提交/恢复与文字迁出 |
| `npm run test:appearance` | 两轴主题、对比度、阅读器/PDF主题协议 |
| `npm run check:docs` | 版本、行数表、路径、链接及提示词等机器一致性 |
| `npm test` | 上述类型、断言与文档检查的串行聚合入口 |
| `npm run prepare:pdf` | 从产品模板生成PDF运行资源，由Lead/CI统一执行 |
| `npm run build:web` | 仅Web编译校验，临时产物同次清理，不是界面预览 |

**不生成HTML界面预览、不启动预览服务、不在本机构建APK。** 已有启动脚本不代表本轮获得运行服务的授权。真机检查需要先接设备、核对安装包来源，每次操作后截图确认；没有设备或图像能力时，只报告实际做过的源码/机器检查。

构建与发布交给[Android CI](<.github/workflows/android.yml>)：准备PDF资源、类型与各组断言、文档检查、生成原生工程、构建APK。获明确授权后，推送主分支可构建，版本tag才会创建Release；本轮不自动push、tag或发布。不要手改原生生成目录，构建配置由[构建插件](<plugins/withBuildOptimizations.js>)维护；在已有本地工程上获准运行prebuild时必须保留 `--no-clean`。
