# 2026-11-15 间距返工与回顾日历（v0.22.0）

> 用户原话：「你一直没有改间距，我很失望」。
> 附四条具体位置，外加一句「参考 jotsy，看哪些功能不错、哪些 UI 可以参考，
> 然后在回顾里加上日历」。本文记录**每条为什么会长成那样**，以及做了什么、没做什么。

## 1. 四条抱怨的根因

四条其实是同一个毛病：**某个元素占了一整块位置，而它不该占。**
前几轮改的是字号、色阶、边框这些「看得见的参数」，间距一直没动，因为
它们不是某个数写错了，而是结构把空白固定下来了。

| 用户说的 | 真正的原因 | 改法 |
|---|---|---|
| 碎片长了，「展开全文」和下一个隔得很开 | 「展开全文」是个 `minHeight: controlHeight`（48）的按钮，下面还压着 `rowBody` 的 14 底距 —— 一条长碎片后面固定空出 60 多 px | 按钮降到 26（一行字 + 2 的留白），触控区靠 hitSlop 补；行底距 14 → 10 |
| 文档页字太大，一个文件的框较大 | 卡片里竖着摞了五行（标题 16/26、摘要 3 行、元信息、状态、48 高的操作按钮），每行还各带 marginTop | 标题 14/21、摘要 2 行 12/18、元信息与状态 12、操作按钮 34 + hitSlop、卡间距 12 → 8 |
| 问页：思考/联网挪到框上面、缩小、框随字数长高但有上限 | 两个开关和发送键挤在框内的同一行，于是框永远是一行高；开关跟着 48 的按钮走 | 开关移到框外一行（34 高），框内改成「文本 + 发送」横排，文本 34 起、5 行封顶 |
| 回顾：待办之间隔得开、子待办字号没区分、一条占太多 | 每行正文独占一行、两个图标按钮另起一行，而 `IconButton` 最小槽是 48 —— 一行待办 96 起；子项和父项都是 14/21 | 图标挤回同一行（新增 `IconButton compact`：36 槽 + hitSlop 补 48）；勾选框 28；子项 12/18；进度和到期合成一行小字 |

**为什么前几轮没动这里**：上一轮的断言钉的是「48 的触控下限」，
于是所有交互元素都往 48 靠 —— 一路加到列表行里，行高就翻倍了。
这次把两件事拆开：**看得见的槽** 可以小，**摸得到的范围** 仍然是 48（hitSlop）。
断言也重写成了钉这条关系（`assert_ui` 里那 5 条新用例），不是钉具体像素。

## 2. 参考 jotsy（CikeSeven/jotsy）

Flutter 写的本地日记应用，GPL-3.0，功能和本项目有大量重叠（本地优先、无账号、
富文本、日历、备份）。看下来值得参考的和不值得的都记在这里，免得下次再翻。

### 采纳

- **月视图只做索引**：格子里不放文字摘要，只放「这天有没有东西」的信号
  （一排小点：记录 / 到期 / 小结），点开某天再展开明细。与时间轴的分工也清楚 ——
  时间轴是流水，日历是地图。
- **固定 6 行 42 格**：翻月时格子高度不跳。jotsy 的月历也是这个做法。
- **月度小结这一行**：`本月 N 条记录 · 记了 M 天 · K 件到期`。
  「记了几天」比「几条」更能说明状态 —— 一天记十条和十天各记一条不是一回事。
- **在日历里直接勾完成**：到期日那天列出来的待办可以就地勾掉，不必回列表。

### 没采纳（记在 ROADMAP）

- 农历 / 节假日 / 调休：要一张每年维护的表，而这里记的是自己的事，不是日历软件。
- 日期格五种样式（圆点 / 心情 / 热力 / 照片 / 标签）：我们只有「记录 / 到期 / 小结」三种事实，
  五种视觉是给「有心情和封面」的日记准备的。
- 年度热力图、那年今日、时间胶囊：都是好功能，但都要先有更大的数据量和另一种阅读节奏。
- 日记本 / 章节 / 模板 / 样式码：那是内容组织与外观定制的整套体系，与本项目「时间轴 + 文档」的取向冲突。

## 3. 这一版做了什么

1. `src/util/calendar.ts`（新）：纯日期网格，42 格、周一开头、`shiftMonth` 跨年、`keyToTs` 走本地时区。
2. 回顾页第三个 tab「日历」：月头 + 翻月 + 今天、点阵格子、月度小结、当天明细（可勾待办、看小结与记录摘要）。
3. `IconButton` 新增 `compact`：36 的可见槽 + 6 的 hitSlop。默认仍是 48，主入口不受影响。
4. 碎片行、文档卡、问页书写区、待办行按上表重排。
5. 问页提示条位置改成**实测**（`onLayout`），不再用 `keyboardHeight + 140` 这个估算值。

## 4. 没验的部分

没有设备，所以以下靠断言和编译校验，**没有真机观感**：

- 日历格子在实际字号缩放下的换行（尤其是 `320dp` + 200% 字号）；
- 待办行把图标挤进同一行后，长文本换三行时的对齐；
- 问页输入框在安卓输入法下的自动长高（RN 的 `multiline` 自适应行为与输入法实现有关）；
- 提示条实测高度的首次渲染（`footerHeight` 初值 120，`onLayout` 之后才对）。
