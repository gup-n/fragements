## 1. 结论

建议沿用现有单机架构，拆开五件事：**保存原件 → 打开阅读 → 按需提取 → 文内查找 → 限定文档问答**。

其中“保存”不是云上传，“打开”不要求先经过 MinerU，“可打开”不等于“已有可检索文本”。不能靠给现有页面加一个多选框就完成这次需求。

主／子 Agent 指开发协作方式，不在手机端另外引入多 Agent 调度、向量服务或大模型运行时。

## 3. 建议的需求基线（待确认）

### 3.1 导入只保存

- 在当前单机定位下，把“上传”解释为**导入到手机本地**，建议按钮叫“导入文件”，避免与云上传混淆。
- 选择文件 → 复制到私有目录 → 核验副本及实际大小 → 保存元数据 → 显示“已保存”。
- 不自动提取全文、不建问答索引、不调用 MinerU、不调用模型；离线、无 Key、无 Token 都应完成本地保存。
- “能保存”“能内置打开”“能本地提取”“能云解析”采用独立能力判断。存储限制不能沿用云端解析的 10/200 MB 配额。
- 原件始终保留；不能提取、空文件、加密文件等是后续能力状态，不等于导入失败。损坏文件可保留并明确提示。
- 保留现有已导入格式与历史文档，不因新阅读器只覆盖部分格式而删数据或阻止外部打开。

### 3.2 阅读与格式范围

建议首版只读，不做 Office 编辑器。

| 格式 | 建议的应用内目标 | 边界 |
|---|---|---|
| TXT | 原文阅读、查找、命中计数、上下条跳转 | UTF-8/BOM 优先；其它编码明确处理或提示，不能把乱码当成功 |
| Markdown | 安全排版＋原文模式、查找 | 普通 `[F12]` 等字符串必须保留；长表格不能静默丢列；不自动加载远程资源 |
| PDF（有文本层） | 按页原版式阅读、缩放、页内／跨页查找 | 本地解码不等于云解析；阅读器与文本提取／坐标能力需一起验证 |
| PDF（扫描件） | 不经 OCR 也能看页面图像 | 没有文字层就说明尚不可查字；OCR 是单独能力，不能伪报“全文无命中” |
| Excel（优先 xlsx，兼顾 xls） | 工作表切换、行列／单元格只读视图、查找并跳格 | 不执行宏、外链或公式，不承诺重算、图表或全部格式与 Excel 一致 |
| Word（docx） | 可放后续；先保留原件打开和用户主动云解析 | 是否首版做本地文本阅读取决于用户优先级，不顺带扩成全 Office |

“打开”必然涉及按需解码，但不是“上传时强制全文解析”。对用户应显示本地读取和云端处理的区别。

外部“用其它应用打开”继续作为兜底；若用户要求应用内查找，不能用外部应用有搜索按钮来代替验收。

### 3.3 文内查找

- 查找框放在阅读器内；显示当前第几处／总数，上一处／下一处、高亮与跳转一致。
- 明确 PDF 全文、Excel 当前工作表／整个工作簿的搜索范围。
- 确定性字面查找与问答 FTS 检索分开：FTS 的 OR/topK 结果不是全部命中，不能用于全文命中总数。
- 超长文档分块搜索和虚拟化显示；如果结果分页或受上限约束，明确显示“99+／继续查找”，不能假装总共只有 99 处。
- 必须覆盖跨粗体边界、代码、表格、中文／英文、特殊字符及同段多次命中；不以“滚到段首”冒充精准逐处定位。

### 3.4 多文档去问

- 文档列表有可见多选按钮与底部“问这 N 份文档”；单篇阅读器也可“问这份”。不是依赖隐藏手势。
- 问页显示当前所选文件，可在发送前检查；建议默认**只查所选文档**，不自动混入笔记、其它文档或网页。
- 一场会话锁定文档集合；换集合开新会话，避免旧答案和旧来源污染新范围。历史恢复使用当时的范围。
- 未准备正文／索引的文件不能静默丢掉：列出哪些可用、哪些需本地准备或单独 OCR，由用户选择准备、移除或取消。
- 点击发送后，把选中文档中本轮实际用到的文本片段发往设置中的 AI 服务；不是默认发送整份原文件。应在交互中说清接收方。
- 远程解析必须单独确认文件、接收方、通道与额度；包括重试。取消后不能承诺撤回已经传给第三方的数据。
- 回答引用可点开当时的片段，并显示文件名＋真实页码／工作表单元格／章节行号；没有定位信息就只标“解析正文第 N 段”，不能编页码。

## 4. 初步技术方向与取舍（不是已批准设计）

### 4.1 分层，不重建知识库

```text
导入层：文件副本＋元数据
  ├─ 原件阅读适配器（PDF / Excel / 文本）
  └─ 用户触发的本地提取，或另外确认的云解析
       ↓ 规范文本＋内容版本＋真实定位信息
       ├─ 文内精确查找与显示位置映射
       └─ 派生切片＋文档专用 FTS → 限定范围问答 → 引用快照
```

- **原件保存、正文就绪、索引就绪分开表达**，重试失败不能让旧可用正文突然不可读。
- 文档切片是可重建的搜索投影，不是新的知识卡，不进入时间轴，也不混入 fragment_fts。
- 沿用 SQLite FTS5＋bigram；不引向量数据库、embedding、服务端或本地大模型。
- 切片按段落／页／工作表行组，保留适量上下文、表头与来源定位。索引基于无损规范文本，不基于裁列后的展示 AST。
- 增加文档内容版本，切片与索引按版本原子替换。来源定位绑定版本；重新解析不能让历史引用漂移。
- 升级只追加迁移，不改 v1–v9；保留旧 id、原件 URI、正文与会话。native/web 同一契约。

### 4.2 阅读器候选

| 选择 | 优势 | 劣势／验证门槛 |
|---|---|---|
| 沿用外部打开＋解析正文 | 改动最小，保留现有能力 | 依赖外部 App；无法保证应用内搜索和原位置跳转，只适合作过渡／兜底 |
| PDF.js＋本地 WebView | 可围绕同一 PDF 文本层实现渲染、查找和页定位；不需云查看器 | 新增 WebView 集成；离线资源、文件桥接、字体与手机内存均须实测；不能假设直接在 Hermes 中运行浏览器查看器 |
| react-native-pdf 等原生组件 | 已提供本地文件、缩放、分页等阅读能力 | 新增原生依赖；仅能显示不代表能全文提取／搜索；Expo Go 不含此组件，需 APK 验证 |
| SheetJS CE＋原生只读表格视图 | 本地读取 xlsx/xls，可保留 sheet／单元格身份 | 不是完整 Excel UI；大工作簿解析内存、日期／数值格式与缓存公式值需要测试，不负责公式重算 |

建议先确认“是否必须内置原版式 PDF”，再做一个小型兼容验证：用同一批测试文件比较 PDF.js 路线与原生路线。**不能只根据官网或 Web 编译成功就宣布 SDK58／RN0.88／目标手机兼容。**

若选择 WebView，它是产品离线阅读器的实现候选，不是给用户搭一个网页预览；仍遵守不启动预览服务、UI 用 APK 真机验收的规则。

新增依赖之前检查实际版本、许可证、漏洞、锁文件一致性及 APK 增量。不直接盲装 npm 上的 xlsx；官方安装说明指出该入口陈旧。也不因官网建议而屏蔽安全扫描告警。

### 4.3 问答必须先冻结的契约

1. **范围**：互斥的 records／selected-documents；空白名单、失效 id、非法 scope 都不得退回全库。SQL 查询、LIKE 降级、历史引用回带均受同一范围限制。
2. **预算**：单切片、单文档、全部文档、历史与完整请求的共同预算。对有相关片段的文档分配最低额度，再补高相关内容；不让第一篇吃完，也不硬塞无关段。
3. **覆盖**：精确提问与“概括全部”使用不同策略。资料放不下时如实标“基于部分片段”；不能用 topK 结果声称读完全文。全面长文总结如需额外模型调用，另报覆盖、进度和成本。
4. **引用**：建议本轮 D 短编号映射真实 docId＋版本＋切片＋定位；快照保存本轮实际发送的片段。保留旧 F/N/T/W；不把 documentId 塞进原本只代表碎片的 sourceIds。
5. **兼容**：历史会话仍可读；旧字段缺失按明确兼容规则处理，非法新数据不能用“兼容”为名放宽范围。删除原文件后保留历史快照，跳原件失效则明确提示。
6. **安全**：文档内容是不可信资料，不是系统指令。引用编号需与本轮真实材料映射求交；代码里的编号不算引用。模型不执行文档里的指令、宏、脚本或自动外链请求。

### 4.4 任务与资源生命周期

- 应用级文档任务登记，单文档互斥；持久状态不能依赖某个页面是否还挂着。
- runId／内容版本校验贯穿进度、写库与引用；取消、删除、切会话后到达的结果不能覆盖新任务。
- 上传、轮询、结果下载都要有可见阶段、取消和总期限；远端不支持撤销时明确说明。
- 启动恢复将中断任务展示为可重试，不自动把文件再发出去；已建远端任务是否能复查须看服务契约。
- 原文件复制后核验实际大小；对压缩包展开量、页数、单元格量、正文长度设经过样本测试的资源界限。
- 删除失败留可追踪清理状态；不能吞掉异常后声称空间已经释放。迁移前准备包含原件和相关数据的可靠备份／恢复点。

## 5. 分阶段实施与验收门槛

| 阶段 | 内容 | 验收门槛 |
|---|---|---|
| 0：确认与设计 | 确认下节问题；冻结范围、状态、定位／版本契约；阅读器选型验证；正式设计审批 | 不以演示能显示一页替代文本搜索和目标 SDK 兼容；未批准不迁库、不安装大依赖 |
| 1：只保存＋生命周期 | 导入与解析分离；状态兼容；云解析入口／再次确认；任务防重与失败可恢复 | 飞行模式、无 Token、超过云解析限额仍可保存；重启原件仍在；导入不发解析／AI 请求 |
| 2：打开＋文内查找 | TXT/MD 无损阅读；Excel sheet／cell；PDF 原件阅读与文字层；统一命中映射 | 每种支持格式能打开、搜到、看到、跳到同一处；扫描／加密／超限有真实降级；不丢列／字 |
| 3：多文档问答 | 派生切片／FTS、会话范围、输入预算、D 引用与快照 | 选 A/B 时 C、笔记、旧会话不得混入；长短文公平装填；真实覆盖与来源定位可核对 |
| 4：集中回归与交付 | 升级／重启／取消／删除／恢复；大文件与真机；文档同步 | 旧数据和旧问答不丢；隐私边界真实；经授权再走 CI APK 与 Release |

复杂度最高的是阶段 2 的 PDF／Excel 适配和长文定位，不是“上传按钮”。具体工期、文件上限与性能指标应在样本规模确定后估算，不在调研阶段虚报。

首轮不顺带做文档编辑、全格式 OCR、本地大模型、向量检索、云同步或全局自动扫描文档。全量文档备份功能可独立规划，但迁移前的可靠恢复点是必须项。

## 6. 主／子 Agent 分工

本轮已经完成两个只读子任务：

- `document-audit`：导入／文件／解析／阅读／查找基础审查，task-1 完成。
- `qa-audit`：检索／引用／会话／多文档范围审查，task-2 完成。
- 主 Agent：读取规范与记忆、Git／基线检查、代码抽查、官方资料核对和本方案整合。

批准后建议仍用两个子 Agent，不为了形式增加数量：

| 角色 | 独占实现范围 | 依赖 |
|---|---|---|
| 主 Agent | 正式规格、共享 types／Repo 接口、双端迁移、路由、共享渲染契约、集成与回归 | 先冻结接口；审查最终 diff；统一交付 |
| 子 A：文档 | 导入／任务服务、原件文件层、阅读适配器、文档页／阅读器 | 读取冻结的内容版本与定位契约，不擅改共享类型 |
| 子 B：问答 | 文档检索与装填、问页、引用展示、会话范围逻辑 | 先用约定夹具实现，再接子 A 的正文产出 |

同一共享文件由主 Agent 负责；任务写入范围不重叠。未满足依赖的集成任务不提前开始。主 Agent 不能把子 Agent 的“通过”直接当成整体验收。

## 8. 需要用户集中确认的三项

1. **阅读要求**：是否按“应用内只读”做，PDF 保留原版式、Excel 可切工作表（推荐）？还是先接受“应用内文本正文＋用外部应用打开原件”的轻量过渡？两者成本和可验收能力不同。
2. **扫描 PDF**：首版是否必须“扫描件也能查和问”？建议保留现有 MinerU 作为手动确认的 OCR／复杂版面解析，默认不联网；如果要求完全离线扫描 OCR，需要另行选型，不纳入默认方案。
3. **实际规模**：常用最大文件约多少 MB／PDF 多少页／Excel 多少行，通常同时选几份问？这些决定阅读器与预算，不能把云解析限额直接当成本地能力。

其它默认建议：沿用单机、只读、只问选中文档；未就绪项先明确提示；换文档集合开新会话；Word 本地增强后置；任何云处理单独告知。
